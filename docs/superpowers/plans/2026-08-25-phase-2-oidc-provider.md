# flare-idp Phase 2 — OAuth 2.1 / OIDC Provider — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A relying party can complete authorization-code + PKCE (with consent, or trusted skip), refresh with rotation, client-credentials, userinfo, introspection and revocation against the Worker; OIDC discovery + JWKS resolve from the bare origin (`https://idp.ros-nett.com/.well-known/openid-configuration`); admins manage OAuth clients through an audited facade; an `oidc-smoke` script proves the flow end-to-end.

**Architecture:** `@better-auth/oauth-provider@1.7.1` joins the plugin list (schema regenerated → ONE new append-only migration). The Better-Auth allowlist becomes method-aware and grows to the protocol endpoints; root `/.well-known/*` rewrites map discovery to `/api/auth/.well-known/*`; the origin/CSRF guard exempts the three client-authenticated endpoints (`token`, `introspect`, `revoke`). The SPA-facing consent decision goes through OUR facade (`/api/oauth/consent`), which proxies a REAL `Request` to `auth.handler` with `oauth_query` (spike S4 + decisions.md: `auth.api.oauth2Consent` cannot be called without one). Client CRUD is admin-only through `/api/admin/oauth-clients` with policy + audit.

**Tech Stack additions:** `@better-auth/oauth-provider@1.7.1` (returns to `packages/api` + `packages/db` gen config). No other new deps (`jose` already a dev dep for tests).

**Spec:** `docs/superpowers/specs/2026-08-21-flare-idp-design.md` (Facade route families: oauth + admin oauth-clients; Identity core; Security posture). **Measured constraints:** `docs/decisions.md` — S4 section + “Consequences for Phase 1” (consent Request-proxy, `application_type: "native"` for loopback, issuer knob) + “Deployment”.

## Core contracts (used across tasks)

**Method-aware allowlist (`packages/api/src/http/app.ts`)** — replaces the string array:
```ts
export const BETTER_AUTH_ALLOWLIST = [
  { path: "/api/auth/jwks", methods: ["GET"] },
  { path: "/api/auth/oauth2/authorize", methods: ["GET", "POST"] },
  { path: "/api/auth/oauth2/token", methods: ["POST"] },
  { path: "/api/auth/oauth2/userinfo", methods: ["GET", "POST"] },
  { path: "/api/auth/oauth2/introspect", methods: ["POST"] },
  { path: "/api/auth/oauth2/revoke", methods: ["POST"] },
  { path: "/api/auth/.well-known/openid-configuration", methods: ["GET"] },
  { path: "/api/auth/.well-known/oauth-authorization-server", methods: ["GET"] },
] as const;
app.on(["GET", "POST"], "/api/auth/*", (c, next) => {
  const entry = BETTER_AUTH_ALLOWLIST.find((e) => e.path === c.req.path);
  if (entry && (entry.methods as readonly string[]).includes(c.req.method)) return auth.handler(c.req.raw);
  return next();
});
```
Root rewrites (same `new Request(url, c.req.raw)` pattern as jwks): `/.well-known/openid-configuration` → `/api/auth/.well-known/openid-configuration`; `/.well-known/oauth-authorization-server` → `/api/auth/.well-known/oauth-authorization-server` (GET only).

**CSRF exemption (`app.ts`)** — the three client-authenticated endpoints get no Origin check (RPs POST server-to-server with no Origin header). Replace the bare `app.use("/api/*", rejectCrossSiteMutations)` with:
```ts
export const CSRF_EXEMPT_PATHS = ["/api/auth/oauth2/token", "/api/auth/oauth2/introspect", "/api/auth/oauth2/revoke"] as const;
app.use("/api/*", (c, next) =>
  (CSRF_EXEMPT_PATHS as readonly string[]).includes(c.req.path) ? next() : rejectCrossSiteMutations(c, next),
);
```
`authorize` stays origin-checked for POST (GET is unaffected by the guard) — RPs use GET.

**Scopes (`packages/shared`)**:
```ts
export const OAUTH_SCOPES = ["openid", "profile", "email", "offline_access"] as const;
export type OAuthScope = (typeof OAUTH_SCOPES)[number];
export const SCOPE_DESCRIPTIONS: Record<OAuthScope, string> = {
  openid: "Sign you in and identify you",
  profile: "Read your name and profile picture",
  email: "Read your email address",
  offline_access: "Stay signed in (refresh tokens)",
};
```
(`orgs` scope arrives Phase 4.)

**Consent proxy shape (`packages/api/src/routes/oauth-consent.ts`)** — the load-bearing part:
```ts
const target = new URL(c.req.url);
target.pathname = "/api/auth/oauth2/consent";
target.search = "";
const proxied = new Request(target, {
  method: "POST",
  headers: new Headers({
    "content-type": "application/json",
    accept: "application/json",                       // forces { redirect: true, url } JSON instead of a 302
    cookie: c.req.raw.headers.get("cookie") ?? "",
    origin: new URL(c.req.url).origin,
  }),
  body: JSON.stringify({ accept: body.accept, scope: body.scope?.join(" "), oauth_query: body.oauthQuery }),
});
const res = await auth.handler(proxied);
for (const cookie of res.headers.getSetCookie()) c.header("Set-Cookie", cookie, { append: true });
```
Non-2xx from the handler → map to 400 `invalid_request` envelope with the upstream `error_description`/`message` when present (parse defensively). 2xx → parse `{ redirect, url }`, respond 200 `{ redirectTo: url }`.

**Client policy (admin facade)** — enforced BEFORE calling Better-Auth, each violation → 400 `invalid_request` with a specific message: `redirect_uris` non-empty, each parses as a URL and is `https:` OR loopback (`http:` with hostname `localhost`/`127.0.0.1`/`[::1]`); if any loopback URI present, `application_type` is forced to `"native"`; requested `scope` ⊆ `OAUTH_SCOPES`; `grant_types` ⊆ `["authorization_code","refresh_token","client_credentials"]`; `token_endpoint_auth_method` ∈ `["client_secret_basic","client_secret_post","none"]`; `client_credentials` grant requires a confidential client (auth method ≠ `none`). `skip_consent` is passed through (trusted first-party clients). The plaintext `client_secret` appears ONLY in the create/rotate responses.
